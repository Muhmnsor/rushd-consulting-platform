# خطة تنفيذ صفحات منصة رُشد

هذه الوثيقة تحول مواصفات الصفحات الوظيفية إلى خطة بناء قابلة للاختبار. تبقى
المواصفات الأصلية مرجع النطاق، بينما تحدد هذه الوثيقة ترتيب التنفيذ وحدود كل
واجهة.

## مبادئ التنفيذ

1. Frappe هو محرك البيانات وسير العمل والصلاحيات، وليس واجهة المنتج للمستخدم.
2. الواجهات منفصلة إلى `public` و`portal` و`staff` و`admin`.
3. كل صلاحية تُطبق في الخادم وعلى مستوى السجل، ولا يعتمد المنع على إخفاء عنصر.
4. تستخدم الصفحات قوالب مشتركة: لوحة، قائمة، تفاصيل، نموذج، تقويم، تقرير.
5. تنفذ الرحلات من بدايتها إلى نهايتها قبل الانتقال إلى وظائف ثانوية.
6. كل واجهة عربية RTL ومتجاوبة مع الجوال منذ أول إصدار.

## المرحلة الأولى: رحلة طلب الاستشارة

### الواجهة العامة

- تسجيل الدخول.
- إنشاء الحساب والتحقق في مرحلة لاحقة من الرحلة.

### بوابة المستفيد

- لوحة المستفيد.
- طلب استشارة جديد مع حفظ مسودة.
- قائمة الطلبات والحالة والخطوة التالية.
- الملف الشخصي الأساسي.

### التشغيل

- طابور الطلبات الجديدة.
- مراجعة اكتمال الطلب.
- طلب معلومات إضافية.
- تحويل الطلب إلى الفرز.

### المشرف

- الفرز وتحديد ملاءمة الخدمة.
- الإسناد اليدوي للمستشار.

### معايير اكتمال المرحلة

- لا يستطيع مستفيد إنشاء طلب باسم مستفيد آخر.
- لا يستطيع المستخدم فتح طلب لا يخصه بتغيير الرابط أو معرّف API.
- تظهر حالة الطلب والخطوة التالية بلغة عربية واضحة.
- لا يعرض API بيانات الحقول الداخلية أو المهنية.
- يعمل النموذج على الجوال ويحفظ المسودة.
- توجد رسالة واضحة بأن المنصة ليست مسارًا للطوارئ.
- تمر اختبارات الصلاحيات والرحلة الكاملة.

## المرحلة الثانية: الموافقات وولي الأمر

- حساب ولي الأمر المستقل.
- الربط والتفويض محدد النطاق والمدة.
- الموافقة ذات الإصدار والتوقيع أو OTP.
- فصل إجابات ولي الأمر عن إجابات المستفيد.
- عدم إظهار الملاحظات المهنية أو روابط الجلسات الخاصة دون سياسة صريحة.

## المرحلة الثالثة: المواعيد والجلسات

- التوفر والحجب ومنع التعارض داخل Transaction.
- الحجز والإلغاء وإعادة الجدولة.
- توثيق الجلسة بثلاثة مخرجات منفصلة:
  - ملاحظة مهنية داخلية.
  - ملخص للمستفيد.
  - ملخص لولي الأمر عند السماح.
- اعتماد السجل ومنع تعديله دون Revision أو Amendment.

## المرحلة الرابعة: الخطة والمقاييس والمتابعة

- الأهداف والمؤشرات والمهام.
- قوالب المقاييس وإصداراتها.
- التقييم القبلي والبعدي.
- النتائج المبسطة حسب سياسة العرض.

## المرحلة الخامسة: الإشراف والجودة والتشغيل

- مراجعة الجلسات والخطط.
- طلبات الإشراف والتصعيد.
- الشكاوى السرية ومنع تضارب المصالح.
- التقارير التشغيلية والجودة الأساسية.

## المرحلة السادسة: الإدارة والمحتوى والتكامل

- المستخدمون والأدوار والنطاقات.
- الخدمات وقوالب النماذج والموافقات.
- الإعلانات والمحتوى حسب الجمهور.
- التكاملات بعد اعتماد البيانات التي يسمح لها بمغادرة رُشد.

## مصفوفة الأسطح

| السطح | المستخدمون | ما يظهر |
| --- | --- | --- |
| `rushd.sa` | الزائر | التعريف والخدمات والسياسات والدخول |
| `portal.rushd.sa` | المستفيد وولي الأمر | الطلب والموافقة والموعد والملخصات المسموحة |
| `staff.rushd.sa` | المستشار والمشرف والتشغيل | الحالات المسندة والفرز والجلسات والإشراف |
| `admin.rushd.sa` | الإدارة ومسؤول النظام | المستخدمون والإعدادات والتقارير والتكاملات |
| `api.rushd.sa` | واجهات رُشد فقط | عقود API محددة بأقل بيانات لازمة |

## الحالة الحالية

- اكتمل قالب بوابة المستفيد العربي والمتجاوب.
- اكتملت لوحة المستفيد.
- اكتمل إنشاء طلب استشارة وحفظه كمسودة وإرساله.
- اكتملت قائمة الطلبات والحالة والخطوة التالية.
- اكتملت صفحة بيانات المستفيد والتحديث الذاتي للحقول الآمنة.
- اكتملت واجهة مستقلة للاستقبال والتشغيل.
- اكتمل طابور مراجعة اكتمال الطلب وطلب الاستكمال والتحويل للفرز.
- اكتملت واجهة المشرف وطابور الفرز وقرارات الملاءمة.
- فُصلت الملاحظات الداخلية عن التوضيح العام الذي يظهر للمستفيد.
- اكتملت لوحة ولي الأمر والمستفيدون المرتبطون وصلاحيات الوصول.
- اكتمل أساس الموافقات: القالب، النسخة غير القابلة للتعديل بعد النشر، وسجل الموافقة.
- اكتملت صفحة موافقات ولي الأمر وتسجيل الموافقة من الويب.
- المرحلة التالية: الإسناد للمستشار والحجز، ثم توثيق الجلسة.
