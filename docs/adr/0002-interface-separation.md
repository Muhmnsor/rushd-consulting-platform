# ADR-0002: الفصل الكامل بين واجهات رُشد

- الحالة: معتمد
- التاريخ: 2026-07-27

## القرار

لا تُعرض واجهة Frappe Desk للمستفيد أو ولي الأمر أو المستشار. تكون الإدارة
واجهة مستقلة في النطاق والوصول، وتكون لكل فئة تشغيلية تجربة مخصصة لا تعرض إلا
المهام والبيانات التي تحتاجها.

## الأسطح

| النطاق المقترح | المستخدمون | الغرض |
| --- | --- | --- |
| `rushd.sa` | عام | الموقع التعريفي |
| `portal.rushd.sa` | المستفيد وولي الأمر | الطلبات، الموافقات، المواعيد، المقاييس والتقارير المسموحة |
| `staff.rushd.sa` | المستشار والمشرف والمنسق | الحالات المسندة، الجلسات، الإشراف والتنسيق |
| `admin.rushd.sa` | الإدارة ومدير النظام | الإعدادات والمستخدمون والتكاملات والتقارير الإدارية |
| `api.rushd.sa` | الواجهات فقط | API رُشد الموثق |

## ضوابط إلزامية

1. لا يكون `admin.rushd.sa` متاحًا للمستخدمين الخارجيين، ويحمى في Azure
   بالشبكة الخاصة أو Access Restrictions، مع MFA للمستخدمين الإداريين.
2. لا تعتمد الصلاحيات على إخفاء عناصر الواجهة؛ كل طلب API يعاد التحقق منه في
   الخادم وعلى مستوى السجل.
3. للمستفيد وولي الأمر جلسات ومسارات منفصلة عن جلسات الإدارة.
4. المستشار لا يرى إلا الحالات المسندة إليه، والمشرف لا يرى إلا نطاق إشرافه،
   والمنسق لا يرى الملاحظات الاستشارية السرية.
5. لا تُستدعى REST API العامة التي يولدها Frappe مباشرة من واجهات المستخدم.
   تُنشأ واجهات API محددة لرُشد وتُرجع أقل قدر لازم من البيانات.
6. ملفات المرفقات الحساسة لا تحمل عبر روابط عامة؛ تصدر روابط قصيرة العمر بعد
   التحقق من الصلاحية.
7. يمكن أن تشترك واجهات المستخدمين في مكونات وتصميم واحد، لكن لكل دور
   Route Guard وNavigation وAPI Scope واختبارات صلاحيات مستقلة.

## الشكل التنفيذي

```text
portal.rushd.sa ─┐
staff.rushd.sa ──┼──> api.rushd.sa ──> Rushd/Frappe ──> PostgreSQL
admin.rushd.sa ──┘                         │
                                          └──> Azure Storage (Private)
```

Frappe هنا محرك خلفي فقط. ظهوره المباشر يقتصر على الإدارة التقنية المصرح لها،
ولا يمثل واجهة المنتج لبقية الأدوار.
